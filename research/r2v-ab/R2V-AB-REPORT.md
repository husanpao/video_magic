# R2V 身份锁定 A/B 实验报告

> 日期：2026-09-23 · 目的：决定是否需要下载 21GB 官方 Ref2VA 权重
> 驱动脚本：`r2v_ab.py`（复刻 `~/comfyui/h3-test-run.py` 的 R2V 分支，只读 ComfyUI HTTP API）
> 配置：FL2VA 剪枝版 21GB + `minimax_h3_fl2v_turbo_8step` LoRA · 864×480 · 124 帧(5.17s) · 8 步 · seed 1688
> 提示词：六段式 Ref2VA（NiliX 实际驱动的格式）

---

## 一、结论

**不需要现在下载 Ref2VA 权重。** FL2VA 剪枝版 + 官方 `MiniMaxH3ReferenceToVideo` 节点
**已经能有效转移角色身份**，跨镜头一致性成立。

**真正的瓶颈不是权重，而是提示词纪律**——文字描述会压过参考图。这是必须让用户知道的运维要点：

> **`subject_definitions` 里用文字写的外貌，必须与参考图一致。**
> 二者冲突时，**文字赢**，参考图被忽略。
> NiliX「同一角色本集所有镜 Subject 描述逐字一致」的要求因此是刚需，且描述必须**照着参考图写**。

## 二、实验设计与结果（共 8 臂，每臂 40 秒）

| 臂 | 提示词 | 参考图 | `ref_image_size` | 输出 |
| --- | --- | --- | --- | --- |
| `base` | 有外貌文字 | 无 | — | (基线，未参与判定) |
| `match` | 有外貌文字 | 王梅(女) | match | 年轻农妇 |
| `ctrl` | 有外貌文字 | **刘富贵(男)** | match | **仍是年轻农妇** ❌ |
| `n_wm` | **中立**(不写外貌) | 王梅(女) | match | **年轻农妇** ✅ |
| `n_lf` | **中立**(不写外貌) | 刘富贵(男) | match | **中年男性·绿军大衣** ✅ |
| `n_s2` | 中立·换场景(背影远景) | 王梅 | match | 背影远景 |
| `n_s3` | 中立·换景别(四分之三近景) | 王梅 | match | **同一角色** ✅ |
| `n_max` | 中立 | 王梅 | **max** | **与 `n_wm` 逐像素相同** |

### 发现 1：参考图确实能转移身份（这是前提验证）

中立提示词下换参考图，**输出人物的性别、年龄、发型、服装全部跟随参考图**：

| 参考图 | 输出 |
| --- | --- |
| `char_wangmei.png`（二十七八岁农妇，靛蓝棉袄，黑辫子） | 年轻农妇，靛蓝棉袄 + 辫子 |
| `char_liufugui.png`（中年男性，绿军大衣毛领） | **中年男性，绿军大衣毛领** |

像素平均绝对差 **34.13**（远超"几乎相同"阈值）。

→ **`MiniMaxH3ReferenceToVideo` + FL2VA 权重不是摆设，参考通路真实生效。**

### 发现 2：文字描述压过参考图（最重要的运维结论）

`match` 与 `ctrl` 用了**同一句提示词**（文字写明"王梅：靛蓝棉袄、黑辫子"），
只把参考图从女性换成男性 —— 输出**仍然是女性**（像素差 24.82，说明参考图有影响，但没改变身份）。

**所以：文字与参考图冲突时，模型服从文字。**

这解释了为什么很多"角色不一致"的问题其实是**提示词里手写的外貌描述**造成的，而不是权重不够。
实测中漏掉的一环是：如果 `subject_definitions` 是照着参考图逐项写的，文字与图一致，身份就稳定。

### 发现 3：同一参考图跨镜头一致

`n_wm`（正面近景，室内窗边）vs `n_s3`（四分之三侧面，油灯下数钱）：
**同一张脸、同一条辫子（红绳）、同色靛蓝棉袄，连参考图里肘部的补丁都对上了**，只是场景/景别/光线不同。

→ **跨镜头身份锁定成立**，这正是短剧最需要的能力。

### 发现 4：`ref_image_size` 在本机当前尺寸下是 no-op（精确解释）

`n_max` 与 `n_wm` 输出**逐像素完全相同（平均差 0.00）**。原因见
`comfy_extras/nodes_minimax_h3.py:296-307`：

```python
if ref_image_size == "match":
    scale = min(1.0, math.sqrt((width * height) / (w * h)))   # 缩到生成像素面积
else:
    scale = min(1.0, REF_IMAGE_SHORT_EDGE / min(w, h))        # 保留至多 2048 短边
```

本机参考图 640×640（面积 409,600），渲染 864×480（面积 414,720）：

- `match`：`min(1.0, √(414720/409600)) = min(1.0, 1.006) = **1.0**` → 不缩放
- `max`：`min(1.0, 2048/640) = **1.0**` → 不缩放

**两者都算出 scale=1.0，因此结果必然逐像素相同。**

→ `ref_image_size` 只在**参考图大于渲染尺寸**时才有效。
本机定妆照 640×640 恒小于 864×480，所以该参数在本机是空操作；
NiliX 画质升级里"`max` 身份保真更强"的结论**在本机当前素材尺寸下不产生任何差异**。
（若将来把定妆照提到 NiliX 默认的 1024×1024，该参数才会重新生效。）

## 四、本次实验的局限（如实说明）

1. **未测官方 Ref2VA 权重**（本机没有）。结论是"当前路径够用"，而非"Ref2VA 无增益"。
2. 走的是 `h3-test-run.py` 的 **T8 双时钟采样器通路**，不是 NiliX 生产工作流
   （后者还有 SigmaShift / CondSave / MotionContext 接缝）。R2V 节点与权重相同，
   身份转移结论应可迁移，但生产工作流仍建议复测一次。
3. 身份判定由 **VLM 目视**（本模型读图）完成，非量化嵌入相似度。
   A/B 结论（换人 → 换人）差异极大，不依赖细微判读；但"跨镜头是否为同一人"含主观成分。
4. 仅覆盖 1 个角色 × 3 个镜头 × 1 组种子，未做多角色/多 seed 统计。

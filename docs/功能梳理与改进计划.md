# video_magic 功能梳理与改进计划

> 生成时间：基于当前工作区代码（v0.1.0 之后）。目标：① 梳理现有功能全景；② 给出 UI / 后台改进意见；③ 形成分期实施计划。
> 文中 `文件:行号` 均为实读代码定位；两条 P0 结论（死路由、抽卡预算漏管）已逐一人工复核确认。

## 一、功能全景

### 1.1 定位

把小说章节变成带配音和中文字幕的漫剧成片，五阶段流水线，**每一步可看、可改、可重来**：
拆镜（DeepSeek）→ 定妆（Qwen-Image / T2VA 抽帧）→ 逐镜渲染（MiniMax-H3 Ref2VA，参考图锁身份）→
机械质检（纯 ffmpeg）→ 合成拼接 + 烧字幕 + 导出 srt。核心纪律是「不压缩」：
台词逐句回原文核对、场景实体逐字注入、角色外貌锁死、提示词六段式不给模型留猜测。

### 1.2 流水线阶段（pipeline.py DISPATCH，CLI/Web 同一入口）

| 阶段 | 模块 | 功能 |
|---|---|---|
| ① 拆镜 `plan` | [vm/plan.py](../vm/plan.py)（2671 行） | 章节 → 镜头表 + 角色卡 + 场景/道具实体 + 六段式 H3 提示词；多章出 `shots/chapterNN.json`；含 DeepSeek 客户端与逐句保真校验 |
| ② 定妆 `chars`/`gacha` | [vm/chars.py](../vm/chars.py)、[vm/costumes.py](../vm/costumes.py)、[vm/assets.py](../vm/assets.py) | 定妆照（T2VA→抽第 24 帧）+ 抽卡候选；服装变体（图锁身份+文控服装）；场景/道具概念图抽卡、上传、采纳 |
| ③ 渲染 `render` | [vm/gen.py](../vm/gen.py)、[vm/comfy.py](../vm/comfy.py)、[vm/qi.py](../vm/qi.py)、[vm/storyboard.py](../vm/storyboard.py) | 逐镜 Ref2VA（跳过→检查点回收→提交→写指纹）；分镜图预演（Qwen-Image） |
| ④ 质检 `qc` | [vm/qc.py](../vm/qc.py)、[vm/audit/](../vm/audit/) | 硬故障/夜戏/尾帧冻结/静音/时长/音画同步机械判定；渲染前审计（节奏、台词覆盖、台词保真、完备性矩阵），纯函数零 I/O |
| ⑤ 合成 `assemble` | [vm/assemble.py](../vm/assemble.py)、[vm/script.py](../vm/script.py) | 按镜头表拼接（xfade 叠化）+ 烧中文字幕 + 导出 srt + 逐章出集；剧本无损视图与 `src_span` 逐字校验 |

### 1.3 Web 控制台（web/，Vue 3 + Vite + Element Plus）

**布局**：顶栏（项目选择/6 阶段按钮/进度/停止/清空重置）+ 四栏工作台（筛选栏 / 场景分组镜头导航 / 镜头表 / 420px 右侧 9 tab）+ 底部胶片条 + 镜头详情弹层 + 右下角抽卡队列浮层。2s 轮询状态与日志，运行中 4s 刷镜头表与当前 tab，任务结束全量补刷（[web/src/App.vue:83](../web/src/App.vue)）。

**核心交互**：
- **镜头表**：7 列（场景/缩略图/台词旁白/景别运镜/时长/状态/操作），7 档派生状态（生成中/已生成/质检可疑/需重渲/待生成/质检不合格/失败），操作按钮随状态改名「渲染/重渲」。
- **镜头详情弹层**（[ShotModal.vue](../web/src/components/ShotModal.vue)）：单镜视频预览 + 分镜图对照、锁定、台词/旁白（含语音预算校验）、六段式提示词**分段/原文双模式**编辑、保存/撤销上一步/AI 重写（带 feedback）/拆分/合并/插入/删除。
- **右侧 9 tab**：日志（增量跟随）、角色定妆（提示词编辑+风格锚警告+抽卡+上传+点图采纳）、剧本（无损校验 gate）、场景、道具（描述编辑+概念图抽卡/上传/采纳）、分镜图、质检（verdict 列表+定位）、审计（findings + 7 维完备性矩阵）、成片（多集 + **分段播放器**：段宽∝实际时长、三色质检标注、点击跳转）。
- **抽卡队列**：入队即返回、连点不卡手、队列管理（取消/清空/停止）。
- **清空重置**：三档范围 + 删除/保留清单预演 + 手输项目名确认 + 自动备份。
- **成本护栏（E3）**：超预算弹「已花 / 卡在哪 / 再放行多少」审批框，一次性放行。
- **E2E 测试**（[web/ui-e2e.mjs](../web/ui-e2e.mjs)）：真浏览器覆盖布局、筛选计数自洽、9 tab、分段条、多章筛选、审批框、控制台零错误。

### 1.4 后台 API（vm/web.py，48 端点 + 媒体流）

- **查询**：projects / status / shots / shot / qc / audit / completeness / script / chapters / storyboard / scenes / props / chars / assets / queue / log / reset/preview
- **任务**：run（8 种 stage）/ stop（精确 pid SIGTERM）/ rerender（单镜）/ approve（预算一次性放行）
- **镜头编辑**：update / lock / rewrite（LLM）/ split / merge / insert / delete / undo / bulk / renumber —— **字段编辑确定性同步进六段式提示词**，保证指纹变化、改动真正生效
- **素材**：chars/gacha、chars/adopt、chars/upload、chars/prompt；asset/gen、asset/upload、asset/adopt；scene/update、prop/update
- **媒体**：`/view`（成片/片段/缩略图/定妆/候选，带 Range）

### 1.5 支撑机制（设计上值得保留的资产）

| 机制 | 实现 | 要点 |
|---|---|---|
| 任务唯一咽喉 | [vm/taskctl.py](../vm/taskctl.py) `start_async` | CLI/Web 同一入口、一份 task.json 互可停止；worker 独立进程 + SIGTERM 8s 看门狗 + 孤儿日志重绑 |
| 镜头指纹 | [vm/state.py:72](../vm/state.py) | md5(prompt+chars+refs@mtime:size+模型参数) → missing/stale/current 三态，改输入只重做相关镜头 |
| 渲染检查点 | [vm/state.py:260](../vm/state.py) | prompt_id 落盘，崩溃后从 ComfyUI `/history` 回收，不重烧 GPU |
| 预算护栏 | [vm/budget.py](../vm/budget.py) | 实测基线（41.8s/镜…）→ 估算 → 超限 409 带结构化载荷 → 一次性放行；按日台账 |
| 队列 | [vm/queue.py](../vm/queue.py) | FIFO 作业队列，drainer 顺序抽干，单作业失败不中断 |
| 审计层 | [vm/audit/](../vm/audit/) | 纯函数、66 项单测全绿，完备性矩阵是「不压缩」纪律的机械化 |
| 进度推导 | taskctl `derive_progress` | 不信 worker 自报，按磁盘产物推导 |

## 二、现状问题诊断

### 2.1 已实锤的功能缺陷（P0）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| B1 | **`/api/budget` 死路由**：handler 已实现但 do_GET 路由链没接线 | [vm/web.py:747](../vm/web.py) 有 `api_budget`；do_GET（:385-436）无此路径；前端 [client.ts:158](../web/src/api/client.ts) 在调用 | 预算面板恒 404，「花多少钱」在 UI 上不可见 |
| B2 | **抽卡不设防**：gacha 阶段 GPU 单价为 0，且预算估算里有 `COST[...] * 0` 死代码 | [vm/budget.py:54](../vm/budget.py) `"gacha": {"gpu_sec_per_shot": 0.0}`；[vm/budget.py:165](../vm/budget.py) | 连点 24 张抽卡烧 GPU 但永不触发护栏 —— 护栏没覆盖全部 GPU 出口 |
| B3 | **queue.json 无锁读改写**：web 多线程 + drainer 进程并发写同一文件 | [vm/queue.py](../vm/queue.py) 全文无任何 lock/flock（grep 证实）；add/claim/finish/cancel 均为 read→modify→write | 并发时丢作业、状态回退 |
| B4 | **写后不刷**：拆分/合并/插入/保存只重载弹层自身，镜头表空闲时不轮询 | [ShotModal.vue:284-327](../web/src/components/ShotModal.vue) 只 `load()`；[App.vue:88-99](../web/src/App.vue) 空闲只刷 tab | 操作完成表格长时间显示旧数据，用户以为没生效 |
| B5 | **批量能力有 API 无 UI**：bulk / 批量重渲已在客户端契约里，全 UI 零调用 | [client.ts:134-145](../web/src/api/client.ts)；grep `*.vue` 零匹配 | 质检列出「需重渲 N」却只能逐镜点 52 次 |
| B6 | **全局错误黑洞**：`state.error` 只写不读；首拉失败白屏无提示；多处静默吞错 | [app.ts:241-243](../web/src/stores/app.ts) 无消费方；[App.vue:109-120](../web/src/App.vue) 无 catch | 网络抖动/后端故障时界面"看起来没事" |

### 2.2 UI/UX 问题

1. 无撤销体系：单步 `api.undo` 只在弹层 footer 一个入口，删除提示「可点顶部撤销」但关弹层后无处可点，无 Ctrl+Z。
2. 确认交互三套并存：5 处 `window.confirm` 与 ElMessageBox 混用。
3. 小屏不可用：四栏固定 grid（[theme.css:63](../web/src/styles/theme.css)），全库无 `@media`。
4. 可访问性弱：`<img alt="">`、分段条 `role="navigation"` 语义不当、全局快捷键寄生在 Filmstrip。
5. 状态管理薄弱：全局单一 `busy`、模块级 `logOffset`、三套轮询定时器（App 2s / QueueFab 1s、3s）；顶栏计数全片口径 vs 筛选计数按章口径对不上。
6. 反馈缺口：刷新按钮无 loading、渲染提交后行内「生成中」要等 4s 轮询、缩略图无 `@error` 容错、重置成功后整页 reload。
7. 行为不一致：胶片条点击开详情、镜头导航点击只选中；剧本 tab 纯文本只读，与镜头表零联动。
8. 重复与类型逃生舱：`.dot.tone-*` 样式三份逐字重复；ScenesTab/PropsTab 成对重复；两份 tab 刷新映射；`as string` / `Record<string, unknown>` 散布。

### 2.3 后台 / 架构问题

1. **巨型文件职责混杂**：[vm/taskctl.py](../vm/taskctl.py) 4189 行 / 147 个函数 ≈ 10 个子系统（进程锁、task.json、进度、只读表聚合、镜头编辑 DSL、六段式拼装、清空重置、LLM 改写、角色表、start/stop）；[vm/plan.py](../vm/plan.py) 2671 行混 LLM 客户端+提示词+三类实体抽取；[vm/web.py](../vm/web.py) 1261 行混 HTTP 框架/静态托管/ffmpeg 缩略图/48 handler，且 `_apply_ref`（:1104）在 handler 里做业务。
2. **路由脆弱**：48 端点靠 if 链手工配对（[web.py:385-509](../vm/web.py)），B1 正是后果。
3. **重复实现**：`_atomic_write_json` 5 份副本；`frames_for_seconds` 与 `shots.seconds_to_frames` 双实现；六段式常量本地副本；「入队+起 drainer」两处重复。
4. **错误处理失真**：上传/采纳把一切异常折叠成 400（[web.py:722、735](../vm/web.py)），服务端 bug 伪装成请求错误；`record_worker_exit` 全吞异常；`queue.drain` 手读 project.json 不走 `load_params`。
5. **测试真空**：核心链路（taskctl/web/state/queue/budget/plan/gen/qc）零单测，48 端点无 API 测试；`qi_test.py` 直接依赖真实项目数据，不可进 CI。
6. **`/api/status` 过重**：每次 2s 轮询全量重算镜头指纹表 + 全阶段 readiness + log_tail。
7. **缩略图同步跑 ffmpeg**（最多 25s）阻塞请求线程（[web.py:104](../vm/web.py)）。
8. **无鉴权**：API 全开放，`serve` 支持 `host=0.0.0.0`（[web.py:1237](../vm/web.py)），而 `/api/reset` 会删文件。
9. **quiet 双响应 hack**（[web.py:1201-1206](../vm/web.py)）：连接复用脏数据的根源。

## 三、改进意见（合并去重，按优先级）

> **v0.2 追加（用户明确提出）：配置中心。** 现状大量配置硬编码在后台，用户抓瞎：
> `comfy_url`（DEFAULT_PARAMS 与 chars/gen/wsclient 多处兜底 `http://127.0.0.1:8188`）、渲染参数
> `width/height/fps/unet/lora/steps`、`llm.base_url/model`、分镜图模型（QI_UNET/QI_CLIP/QI_VAE/models_root
> 走环境变量）、字幕字体（assemble.py FONT_CANDIDATES 硬编码路径）、预算 `budget` 段（可读不可改）、
> 风格与帧网格上限。改进 C1：**配置中心**——全局默认 + 项目覆盖两层、schema 校验、每项带
> 「是什么/改了影响什么/会不会让镜头变 stale」说明、`/api/config` + `/api/config/validate` 预检
> （ComfyUI 连通/模型存在/字体可用）、UI 设置面板（分组、继承/覆盖可视化、危险项影响确认）。
> API key 维持「只走环境变量/密钥文件」纪律不变。

## 五、不做的事（明确边界）

- **跨镜动作连续性**：README 已判定观感可接受、暂不投入，维持现状。
- **文字控画风**：已知局限（画风由参考图决定），改进只做到「换风格=换参考图」的引导提示，不做风格迁移功能。
- **多用户/云端**：定位是本机单人工具，鉴权只做到「不误伤局域网暴露」，不做账号体系。

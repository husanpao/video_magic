# v0.2 交付说明（草案 · 数字待终验回填）

> 主题：健壮性 + 用户体验 + 配置中心。多团队并行开发（backend-hard / config-center / ux-core / ux-tabs / test-guard + Lead 集成）。

## 一、这次「不一样」在哪

### 1. 配置中心：终结「后台固定、用户抓瞎」（全新）
顶栏 ⚙ 设置 → 35 项配置 / 7 组（连接/渲染/模型/字幕/合成/预算/风格）：
- **每项三段说明**：是什么 / 改了影响什么 / 会不会让镜头变 stale —— 直接摊开写，不藏 tooltip
- **三层配置**：builtin ← `~/.config/video_magic/config.json` ← `projects/config.json` ← `project.json`；继承/覆盖标记 + 一键恢复继承
- **保存前预检**：ComfyUI 连通 / 模型文件存在 / 字体可用 / ffmpeg / API Key（key 永不展示、永不落接口）
- **危险项影响清单**：改分辨率/帧率等进指纹的项，先摆出「哪些镜头会变需重渲」再确认
- 字幕样式、帧网格上限等原硬编码项全部可配（缺省逐字节一致，不改配置零行为变化）

### 2. 交互闭环：从「看」到「改」不断流（全新）
- **批量操作栏**：多选 + 全选当前筛选，批量重渲/锁定/解锁/改运镜/删除
- **写后即刷 + 乐观更新**：拆分/合并/插入/保存立即反映到镜头表（修掉「操作完表格没变」）
- **全局撤销/重做**：Ctrl+Z / Ctrl+Shift+Z + 顶栏常驻按钮，多级历史
- **快捷键体系**：←/→ 切镜、E 编辑、R 重渲、L 锁定、/ 搜索、Ctrl+S 保存、? 帮助浮层
- **QC/审计行动闭环**：质检「需重渲 N」一键全部入队；审计 finding 一键重写该镜提示词
- **成片时间线**：分段条拖拽 scrub、hover 出缩略图+台词预览卡、点击联动选镜
- **剧本↔镜头表联动**：丢句红标「⚠ 没进任何镜头」、点击直达镜头、双向定位
- **统一确认组件**：全库 window.confirm 清零，破坏性操作先摆清单再确认
- **阶段 stepper**：6 阶段进度一目了然，运行中高亮 + 真实 done/total
- **全局错误条**：网络抖动/后端故障不再无声白屏
- **暗色模式 + 响应式**（T7）：跟随系统 + 手动切换；小屏可用

### 3. 健壮性：抓出并修复 3 个真 bug + 并发安全 + 预算全覆盖
- **修复**：①渲染检查点回读损坏（崩溃恢复必扑空→白烧 GPU）②/api/budget 死路由+参数错传 ③帧换算双实现 9 处分歧（半帧值差 17 帧）
- **顺手修复**：「插入新镜」按钮契约坏死（发布尔而非锚点镜头号）——此前点了没反应
- **队列并发安全**：queue.json 双层锁（threading+flock），4 进程压测 180 入队零丢失、144 认领零双领
- **预算护栏全覆盖**：抽卡/队列作业全部计价过闸（原抽卡单价为 0=不设防），超预算弹「已花/卡在哪/再放行」审批框
- **/api/status 减负**：指纹表缓存化，7.3ms→0.71ms（约 10×），空闲轮询开销降 ~90%
- **缩略图异步化**：请求线程不再扛 25s ffmpeg；占位图 + 自动重试换真图
- **错误处理收敛**：输入错误 4xx 人话 / 服务端 bug 500 + 留栈；路由表化 + 启动自检（漏注册起不来）
- **测试从 66 项 → 161 项**（后端 95 + 审计 66），E2E 12 组新用例 + 合成夹具自治（不再依赖真实项目数据）

## 二、API 契约变化
1. `GET /api/budget` 正式生效（原 404）
2. 新增 `GET/POST /api/config`、`POST /api/config/validate`
3. `/api/queue/add` 响应新增可选 `needs_approval` 载荷（抽卡超预算审批）
4. `/view?thumb=1` 未命中可能回占位图 + `X-Thumb-Pending: 1`（原同步等真图）
5. 错误分流收紧：已知输入错误 400（原可能 500），服务端 bug 500 + stderr 留栈
6. 成本台账：queue 作业按实际张数逐笔记 `queue:<kind>`
